# weFit · 健康管理

个人健康管理网页：概览 / 饮食 / 运动 / 身体数据 / 历史 / 设置（营养目标 · 习惯打卡管理 · 基础资料 · 个人食物/动作库管理 · 数据备份都在设置页；食物库与动作库点进去是**独立页面**，页面顶部一行带「‹ 返回」与标题）。
运动支持**力量（总次数 + 重量）与计时（总时长 + 可选距离）两类记录**：跑步、骑行、游泳、跳操、操课等以时间计的运动不再需要硬填次数。**运动页是周视图（顶部周汇总卡 + 每天一张全宽卡竖排，可整周前后翻，版式对齐饮食页），添加 / 修改 / 删除全部是**逐项**的**：一天一条安排、每项单独打勾（像每日打卡那样），卡头「＋ 添加运动」加一项（**只能从动作库选动作，力量/计时方式自动设定**）、行尾 ✏️ 打开编辑弹窗改那一项（删除也在弹窗里，行尾不再单放 🗑）（删掉最后一项就回到未安排）；**重量可不填**（不填就不显示重量）。当天任一项打勾就算已运动，计划与完成情况在同一张卡上一眼看清。
饮食的记录弹窗是**三 tab**：**我的库 / 系统库 / 新增**，底下「实际吃了多少克 + 实时合计（kcal/蛋/碳/脂）」三个分页共用。**从库选（自己的或系统的）只需填吃了多少克**，营养按库锁定并只读回显；**从系统库选或新增**时可勾「同时保存到我的食物库」（系统库里自己还没的默认勾上、已同名的标「已有」且折叠不勾；新增默认不勾），入库带的**营养来源**（USDA / 用户）沿用源条目。已记录的餐项行尾 ✏️ **只能改克数与删除**（记录时营养已定格，不会反过来写食物库）。
零 npm 依赖全栈（Node 内置 `http` + `sqlite` + `crypto`），`node server.js` 即起。

## 快速开始

```bash
./start.sh          # Linux/macOS（Windows 双击 start.bat）
```

浏览器打开 `http://localhost:8123`（手机：同一 Wi-Fi 下打开启动窗口打印的电脑 IP 地址）。

## 账户与数据隔离

- 打开页面需**注册/登录**，每个账户只看得见、改得动自己的数据；多人同时使用互不影响。
- 同一人的手机 + 电脑登录**同一账户** = 自动同步（服务器为准，浏览器留离线缓存）。
- 会话 30 天有效，服务器重启不掉线；退出登录：右上角头像胶囊 → ⎋ 退出登录。
- 断网照常记录；恢复后自动补推。若离线期间还关了页面、且本账户其他设备有新数据，重开会弹窗让你二选一，不会悄悄丢改动。
- 食物/动作是**双层库**：人人有自己的"我的库"（可增删），公共"系统库"由管理员在后台维护、对所有人只读，可一键挑进我的库。食物条目带**营养来源**（`src`）小签：系统库条目 = `USDA`，用户自己录入的 = 「用户」，从系统库挑入的沿用其来源。动作带三层信息——**大类**（力量/有氧/课程/球类/柔韧/其他）、**部位**（胸/背/腿/肩/手臂/核心/全身）、**记录方式**（计次/计时），库列表是一张平铺表格（名称 | 分类 | 方式）。

## 管理后台（仅管理员）

访问 `http://<服务器>:8123/admin`（管理员在用户端设置页「🛠 后台管理」卡里也有入口链接）。非管理员账户登录后台会看到"无管理权限"页。

- **系统共享库**：分「食物库 / 动作库」两个子分页，各用一颗「＋ 添加」按钮开弹窗录入（列表行尾 🗑 删除；食物弹窗可填**营养来源**，默认 `USDA`），保存后对所有用户的"系统库"页生效
- **用户管理**：查看全部账户（含数据概况）；**设为/撤销管理员**（系统至少保留一名）；**重置密码**（该账户全部设备强制下线）；**删除账户**（级联清空其全部记录，不可恢复）

## 目录

- `public/` 前端（无构建：`index.html` + `admin.html` + `css/style.css` + `js/seed-data.js` + `js/sleep-shape.js` + `js/app.js`）
- `server/` 后端 + `data/jjhealth.db`（SQLite，全部数据都在这里）
- `MEMO.md` 项目备忘录（架构、功能、技术债、使用备忘）
- `CHANGELOG.md` 版本变更日志
- `PLANS.md` 后续开发计划建议

## 测试

```bash
cd server && npm test                        # 一次跑完下面五个文件
     node test/roundtrip.test.js   # 鉴权 + 双账户隔离 + 往返保真（67 项）
     node test/admin.test.js       # 管理后台 API：角色/重置密码/删号护栏 + 系统库三件套白名单（44 项）
     node test/sleep-shape.test.js # 睡眠形状契约纯函数（前后端共用同一份，16 项）
     node test/migration.test.js   # 破坏性迁移（sets 拍平 / 计划记录合并）+ 同版本第二步就地补列：下放 done、rev 不变、回填只做一次（39 项）
     node test/render.test.js      # 前端渲染逻辑无头验证：启动冒烟 + 六页导航 + 页面记忆 + 结构/数据流/纯函数断言（105 项，零依赖 node:vm 桩；布局/视觉仍需目测）
```

> 睡眠的形状规则（脏值清洗、段数上限）只写在 `public/js/sleep-shape.js` 一处：浏览器先于 app.js 加载它，`server/mapper.js` 直接 require（同 seed-data.js）。改规则只改这一份，两侧自动同步。

浏览器调试钩子：`?ftest`（功能自测）、`?selftest`（全视图渲染）、`?shot=视图名`、`?probe`（数据摘要）。

> ⚠️ `?selftest`、`?ftest` 与 `?shot` 都会先用**演示数据覆盖当前账户**并自动同步到服务器（真实数据丢失）。三个钩子共用同一确认弹窗（v4.4 起，`?selftest` 之前漏检），【取消】则按真实数据正常进入，且确认/取消后钩子都会从地址栏剥除（避免书签/刷新反复触发）；自动化场景可在 URL 追加 `&devok` 跳过确认。

> ⚠️ **v4.12 的运动数据变更（分两步，按来源库分别触发）**：① **破坏性重置**——从 **v4.11 及更早**升级会清空周计划与旧运动日志（`plans` 键、`plan_defs`/`plan_items` 取消），各账户 `rev` +1，请先备份 `server/data/jjhealth.db`；② **就地补列**——从 **v4.12 中间态**（已合并、尚未逐项打勾）升级只给 `workout_items` 补 `done` 并把旧的整天完成下放给它的每一项，**不删数据、不动 `rev`**（`workouts.done` 仅废弃，不删除）。个人动作库、饮食、身体、睡眠、饮水、习惯、账户与食物库两步都不受影响；第二步完成后运动页不再分「计划 / 记录」两个 tab。**已打开的旧页面请强制刷新**（旧 `app.js` 不认识新结构）。

> ⚠️ **v4.11 破坏性版本（历史）**：若你从 v4.10 或更早版本升级，运动项由 `sets` 数组拍平为列、`workout_sets` 表取消，旧运动数据与个人动作库同样会被清空（v4.12 才取消清动作库）。饮食、身体、睡眠、饮水、习惯、账户与食物库不受影响。

> v4 升级说明：v3 及以前的旧成员数据不再展示（"从零开始"决策）；需要留底先备份 `server/data/jjhealth.db`。局域网内即开即用；公网部署请先上 HTTPS（详见 MEMO.md 技术债）。
